# 成品日检管理系统架构

用户提供的完整需求是本项目的执行依据。Python 3.12+、PySide6、SQLAlchemy 2、SQLite、openpyxl、PyQtGraph；单机离线，不需要服务器。模块按用户给定阶段连续实现。

## 数据边界

- `app/core`：版本、路径、日志、输入模型、应用服务容器。
- `app/database`：ORM 表、SQLite 会话、迁移和初始字典。
- `app/services`：检验、统计、字典、Excel、备份、配置、演示数据。
- `app/ui`：七个页面、对话框、表格和图表。UI 只调用服务，不执行 SQL。
- `tests`：真实临时 SQLite、合成工作簿、Qt 离屏交互；不修改用户数据库。

数据库持久化于 `%LOCALAPPDATA%/Product-QC-Daily/database/product_qc.db`；跨平台开发使用用户数据目录；`QC_DATA_DIR` 可以覆盖。打包资源使用 `sys._MEIPASS`，永远不把用户数据写入资源目录。启动使用单实例锁，SQLite 外键、WAL、busy_timeout 和 integrity_check。每次服务操作独立事务，记录与不良明细一起提交。

记录与不良项目通过关联表规范化保存。旧 Excel 只知道某种不良是否出现，通常不知道逐项件数：导入的 `quantity=NULL`，不能臆造为 1 或平均分配。不良率是“不良件数 / 抽检件数”；合格率与返工率按批次；缺陷排名可按出现批次或已知件数统计，两者不混淆。同一不良件可有多个缺陷，明细合计允许高于不良件数。删除为软删除，回收站可以恢复。演示数据标记 `demo`，默认统计和查询排除演示。

## Excel 兼容

默认识别可见的 `成品日检表`，不同时导入隐藏的旧副本。导入先预览和校验，再原子导入正常记录；保留原填写 ID，重复导入幂等；同 ID 内容变化报告冲突。签名从 WPS DISPIMG 和普通图片中提取为受控目录的图片文件。原文件保持不变。

仓库提交脱敏的空模板（保留布局、24 项字典及图表，不提交原始记录和签名）。兼容导出填充模板，修复年月和周区间统计、24 项汇总与排名；标准报表附独立不良明细表，保留数量是否已知。Windows 安装 Excel 时优先 COM 刷新保存；没有 Excel 时仍可正常保存数据库并使用 openpyxl 导出。WPS 私有图片对象转换成普通 Excel 图片；不能承诺保留所有第三方私有对象。

## 备份、迁移和恢复

SQLite online backup 创建一致性快照，不直接复制正在写入的主库。备份附签名目录快照与校验信息；每日首次启动备份，可配置保留天数。恢复先校验备份、版本、完整性及外键，再备份当前数据库；关闭连接后原子替换，失败回滚；恢复后重新加载设置和 UI。迁移有版本记录和升级前备份；拒绝未知未来版本。

## 性能与发布

分页默认 50 条；排序白名单和日期、组别、工单等索引；聚合在 SQLite 完成。导入、导出、备份和大量演示数据使用 Qt worker，主线程只更新 UI。Windows CI 执行测试、PyInstaller onedir 打包、真实 EXE 自检，上传可下载的 ZIP。升级只替换程序目录，用户数据独立保留。P2 权限系统、自动更新服务器和正式抽样标准不属于首版。
