## 用户操作

- 原表统计：打开“数据分析表”，在 A2 选择月份，选“全部”恢复整个导出范围。上方三图为所选期间，下方三图为该期间结束日期所在周；周可跨到相邻月份，但只统计当前导出的记录。
- 原表明细：在“成品日检表”的“时间”列筛选所需月份。明细报表继续在“月份”列筛选。明细筛选与分析页统计月份是各自工作表的操作。
- 不良项目直接显示中文名称。重新导入时如手工改名而未同步对应编码/字典，会明确报错核对，不会静默按旧编码写入。
- 此次调整不会删除既有数据库、记录或签名。升级只替换程序文件夹，不删除用户数据目录。

## Excel 验证证据

`scripts/check_excel_recalculation.py` 使用真实 LibreOffice Calc 加载、重算、保存 XLSX，再重新读取公式结果及内部图表 XML。预期结果来自独立写明的模拟记录与数值，不调用生产统计代码作为预期值。

九个场景：全年、一月、二月、空月份、十二月、跨年全部、跨年一月、闰年2月29日、已保存一月再次切回全部。逐张验证六图系列、`c:f`、`numRef/strRef`、缓存、点数和索引与重算后的单元格一致；检查无公式错误。实际结果见 [recalculation-v1.1.46.json](recalculation-v1.1.46.json)。Ubuntu CI 同样必须运行，不以缺少计算引擎跳过。

两份用户原文件 `成品日检表(4).xlsx`、`成品日检表(5).xlsx` 均用于1825条模拟记录的结构比对；文件哈希保持 `4a3010809b18659656b38882c330a88f976e80553a0e04e8a0e9d935110d3ce1`。验证四表、六图位置/尺寸/颜色/坐标轴、原列定义、合并、字体、边框、填充、日期格式、页边距、冻结与完整打印范围；唯一授权显示变化是中文项目换行及所需行高，另恢复原位置统计控件。见 [template-audit-v1.1.46.json](template-audit-v1.1.46.json)。没有提交原始生产记录或用户签名。

继续执行既有独立 SQLite/OOXML 矩阵：0、1、11、499、500、501、5000、10000 条，两种格式；2026年1825条/365天、2024年1830条/366天；年月日、跨月、跨年、空数据、来源隔离、逐字段记录与逐项不良、六图与两张月度图、打印及重载。统计与导出快照定义沿用 v1.1.45。

## 测试与发布

本地最终全套 `pytest -q` 为287 passed（442.58秒），包括新增分组列宽回归；Ruff通过。隔离目录的启动器自检已复现旧筛选边界失败，修正并增加上述断言后完整通过。最终发布仍须以 PR 最终提交及合并后精确 main SHA 的完整 CI 为依据，运行结果与 Release SHA-256 记录在 PR/Actions/Release 中。

门禁顺序：Windows/Ubuntu pytest + Ruff → Ubuntu 实际重算 → Windows PyInstaller onedir → 真实未签名构建的签名校验/拒绝未签名失败路径 → 可配置签名与校验 → 实际 EXE self-test → main SHA Release。签名启用后，配置缺失、无效签名或未签名二进制、主EXE发布者不符/缺时间戳均阻止发布。ZIP 内附 `signature-verification.json`、`verification.json`、`office-availability.json`，外部提供 ZIP SHA-256。

签名服务的成功签名分支需要维护者提供经过身份验证的账户后才能实测；当前不能标为已通过，也不能把未签名 EXE 的信任问题标为解决。配置说明见 [windows-signing.md](windows-signing.md)。
